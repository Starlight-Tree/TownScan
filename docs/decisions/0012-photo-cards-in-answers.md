# 0012 件数と候補の一覧の回答は、写真のカードで見せる

状態: **承認（2026-11-26。案にユーザーが「y」、直した実画面にも「y」）**。[ADR 0010](0010-candidate-wording-and-count-card.md) の「件数の回答は表で見せる」を改める。呼び名の決まり（[ADR 0010](0010-candidate-wording-and-count-card.md)・[ADR 0011](0011-class-labels-by-observation.md)）は変えない。

## 背景

- このアプリの主題は画像の検出なのに、件数の回答は本文の次が文字の表で、写真は「詳細」を押すまで見えなかった（ユーザー指摘）。
- 表の候補 ID（`c-x-y-n`）は内部の番号で、利用者の判断に使わない。分類の列は、同じ札が続いた（同じ指摘）。

## 決定

- 件数と候補の一覧の回答は、**本文の次に、候補ごとの 2018・2023 年の写真のカード**を出す。はじめは 4 件。
- **候補 ID は画面に出さない**。「詳細」の読み上げの名前・写真の説明・詳細の画面には残す。
- **分類の列は無くすが、分類の情報は残す**（写真の読み方に要る）。件数の回答は分類の見出しで区切る。一覧の回答は面積の順を保つため、見出しで区切らず、各カードに添える。
- 件数の回答の「根拠を見る」は、地図と対象・条件のあとへ移す。
- 比較の回答は、地区どうしを比べるものなので、グラフのまま。API と DB は変えない。

## 見送った案

- **表に小さい写真の列を足す**: 写真が小さく、2 つの年を比べられない。
- **一覧の回答も分類の見出しで区切る**: 面積の順位が崩れる。

## 影響

- 誤検出も最初から目に入る。実データでは、一覧の最初の 4 件に、川と鉄橋の写真（142.25 m²・端のため未判定）が入る。結果を目で確かめるアプリなので、隠さない。
- 写真の読み込みが増える（1 件で 2 枚。はじめは 8 枚。隠れている候補は読み込まない。画像は `loading="lazy"`）。
- 模擬の一覧の本文は「候補の ID を使って、写真を聞ける」と案内するが、画面に ID が無くなった。本文は API の側で、今回は直していない。
