# 0002 方向: 画像認識を核に、GEE を後半の薄い層として足す（B 案）

状態: **承認済み**（ユーザー、2026-11-24「それで進めて」）。

## 決めたこと

- **核:** 熊本市の中心部で、空中写真から建物を抽出し（事前学習モデル）、2 時点（2018・2023）の差分から**新規出現候補**を出す。評価の参照は写真と同時期の版。新築の再現率は手ラベル。（2026-11-27 に改め: [ADR 0014](0014-new-building-recall-unmeasured.md)。手ラベルは使わず、新築の再現率は未測定）（同日にさらに改め: [ADR 0015](0015-move-to-france.md)。対象地域はフランス。新築の再現率は、公開データ FOTBCD で測る）
- **拡張 1（後半）:** Google Earth Engine で、衛星の年次埋め込み（AlphaEarth・10 m・2017〜2025 年）の差から、広域の「変化の当たり」を事前計算し、チャットの道具に足す。チャットの完成後に、小検証の結果を見て go/no-go を決める。
- **拡張 2（その後）:** 屋根のパネルの画像認識。
- 順序: 建物抽出と評価 → 2 時点差分・集計 API・DB → チャット → GEE 層 → パネル → 公開。

## 理由

- 建物データ（基盤地図情報）の差分は新築の検出器にならない（ADR 0001。東京 0/24・熊本 0/20）。写真からの画像認識が要る。
- 無料の地理院の写真は、熊本で 2023 年止まり。GEE は 2025 年まで見られる。「新しい変化の当たりは GEE、棟の確認は写真」と役割が分かれ、互いの弱点を補う。Google 自身も、Detect change の結果を過去の高解像度写真で確かめるよう勧めている。
- 道具を使い分けるチャットは、見せ場になる。核が崩れないよう、GEE は後半の薄い層にする。

## 選ばなかった案

- A（現行のみ）: 見せ場が少ない。ただし GEE の go/no-go が no なら、結果としてここに戻る。
- C（GEE 中心）: 題材が「新築 1 棟」から「地区の変化」に変わり、調査と UI モックのほとんどが使えなくなる。10 m では棟の確認ができない。

## 守る条件（GEE 層）

1. GEE の結果は「変化の当たり」と呼び、「新築」と言わない。
2. 写真が無い期間（2024〜2025 年）は、UI で「棟の確認は不可」と明示する。
3. 公開デモは、GEE の結果を事前計算して静的に配信する（非商用の月次の枠を共有しない。商用に切り替えると枠は引き継がれない）。
4. チャットの完成後に回す。始める前に小検証を挟む: 熊本の 2018→2023 で、ヒートマップが手ラベルの新築棟を何割拾うか。（2026-11-27 に改め: [ADR 0014](0014-new-building-recall-unmeasured.md)。何を正解にするかは未定）

## 調べたこと（2026-11-24。公式ページの検索で確認。原文の全文は未精読）

- [Earth Engine の非商用ティア](https://developers.google.com/earth-engine/guides/noncommercial_tiers): 2026-04-27 から、非商用は月次の計算量の枠（Community 150・Contributor 1,000 EECU 時間）。使い切ると制限モード。年 1 回の再確認。
- [detect change（Google Earth）](https://developers.google.com/maps/documentation/earth/detect-change): AlphaEarth の埋め込み上で、2 つの年（2017〜2025）を比べ、10 m のヒートマップを作る。結果は過去の写真で確かめるよう案内。**Google Earth の機能で、アプリから API で呼べるかは未確認。**
- [AlphaEarth Foundations](https://deepmind.google/blog/alphaearth-foundations-helps-map-our-planet-in-unprecedented-detail/): 10 m・年次・64 次元の埋め込み。
- [Importing Raster Data](https://developers.google.com/earth-engine/image_upload): 自前の GeoTIFF を取り込める（地理院の写真は標準カタログに無い）。
