# 0003 チャットの LLM: Gemini の無料キーを、任意の実モデルとして選べるようにする（当初の既定は模擬。2026-11-25 の追記で、開発・実行の既定を Gemini に変えた）

状態: **承認済み**（ユーザー、2026-11-25「いいよ　さっさとつないで試してよ」。LLM は Gemini の無料キー）。実装は済み。**実 API での動作は、キーが `.env` に入ったあとに確かめる（この文書の時点では未確認）。** 既定のモデル・再試行・待ちの上限は、末尾の「追記 2026-11-25」が新しい（本文は当時の記録として残す）。

## 決めたこと

- `LLM_PROVIDER=gemini` を選ぶと、チャットの「どのツールを呼ぶか」と「結果の説明文」を、Google AI Studio の Gemini（function calling）が作る。**既定は `mock`（模擬モデル）のまま**。環境変数が無くても、いままでどおり動く。
- LLM の役割はその 2 つだけ。**数字・件数・座標・面積・ID は書かせない**（plan.md の方針。**2026-11-26 に改めた: 結果にある数字は書いてよい。[ADR 0009](0009-llm-writes-result-numbers.md)**）。結果（件数・表・比較・地図・写真・精度・断り）は、模擬のときと同じく、ツールが DB から作る。`results`・`tool_calls` の形は変えない。
- 返答文は、模擬と同じ `guard_numbers` を通す。LLM が結果に無い数字を書いた文は、安全なテンプレートに替わる。
- 環境変数は `LLM_PROVIDER`・`GEMINI_API_KEY`・`GEMINI_MODEL`（DocuNavi と同じ名前）。モデルの既定は `gemini-3.1-flash-lite`（DocuNavi の docs/configuration.md が既定にしている、無料枠のチャット用のモデル。**TownScan の用途で関数呼び出しが通るかは未確認**）。
- 上限: モデルへの往復は最大 4 回、ツール呼び出しは最大 6 件、1 回の往復の待ちは 20 秒（接続・受信の段階ごと。全体の締め切りではない）。超えたら失敗。
- 失敗（キー無効・429・5xx・タイムアウト・壊れた応答・上限超過）は、**模擬に黙って切り替えず**、HTTP 502（「いまは LLM が応答できません。少し待ってからもう一度お試しください」）で返す。frontend の既存の失敗表示（送信できませんでした＋もう一度送る）がそのまま使える。ログと応答に出すのは、失敗の種類・HTTP のステータス・Google の理由の定数だけ。
- 仕様は [spec-prototype.md](../spec-prototype.md) の §2.2・§4.4・§4.5。

## 理由

- 模擬モデルは、固定の規則で意図を選ぶので、言い回しの揺れに弱い。実 LLM をつなぐと、このアプリの見せ場（会話でツールを使い分ける）が、規則の外でも通じるかを確かめられる。
- 「数字は結果からだけ」の仕組み（ツールの結果 → `guard_numbers`）が、LLM を入れても崩れないことを、実機で確かめる機会になる。
- 無料キーなので、費用は出ない（課金する実 API ではない）。キーは使い捨てにできる。
- **失敗を隠さない**: 模擬に切り替えると、利用者は実 LLM の答えと取り違える。画面の印（「モデル: gemini」）と食い違うので、失敗は失敗として返す。

## データの扱い（確認していないことを、確認済みと書かない）

- **Google へ送られるもの**: 会話の末尾 20 件（利用者が書いた質問の文面と、アプリの前の返答文）、システムの指示（規則・地区の名前と区。座標・件数・ID は入れない）、ツールの結果（件数・表・比較・精度の数字と、地区名・候補の分類。出どころ・座標・画像の URL・候補 ID の長い一覧は除く）。写真・座標・DB の中身そのものは送らない。
- **無料枠の利用条件（入力が製品改善・学習に使われるか、保存期間、地域の制限など）は、今回は公式ページで確認していない。** 参考として、DocuNavi の docs/configuration.md には「無料枠のキー（請求の無いプロジェクト）は、レート制限が厳しく、入力が製品改善に使われる扱い」とあるが、これは DocuNavi 側の記述で、TownScan では未確認。公式の規約を読んで確かめるまでは、**質問に、個人情報・機密を書かない**前提で使う（このアプリの題材は、公開の空中写真と、機械が見つけた候補の件数だけ）。
- 公開デモ（plan.md の P7）で他の人が触れる状態にするときは、質問の文面が Google へ出ていくことを、画面で知らせるか、実 LLM を切る。この決定の範囲外（その段で決める）。

## キーの置き場

- `GEMINI_API_KEY` は、利用者が自分で置く。置き場は [ADR 0004](0004-secrets-infisical.md) のとおり Infisical が正で、使わないときは TownScan の `.env`（Git の管理外）に書く（以下は `.env` の場合）。`.env.example` には、名前と空の行だけ。`compose.yaml` は `${GEMINI_API_KEY:-}` で api へ渡すだけで、値を持たない。`scripts/dev-up.sh` はキーを作らず、書かない。
- キーは、repr・ログ・例外・応答（`/api/health` を含む）に出さない。Google へは、URL の `?key=` ではなく、ヘッダー `x-goog-api-key` で送る。リダイレクトは追わない（キーを別のホストへ送らない）。
- 誤って出したら、AI Studio でキーを無効にして作り直す（履歴から消すだけでは足りない）。

## 模擬との違い

| | 模擬（既定） | Gemini |
|---|---|---|
| ツールの選び方 | 日本語の規則（正規表現） | モデルが function calling で選ぶ |
| 説明文 | 結果から作るテンプレート（毎回同じ） | モデルが書く（数字は書かせない。書いたら guard が替える。→ 2026-11-26 に、結果にある数字は書いてよいと改めた。ADR 0009） |
| 範囲外 | 規則で `refuse` | モデルが `refuse` を呼ぶ。その文は、年以外の数字を含むと固定の文に替える |
| 地区の指定 | 名前の部分一致 | システムの指示に地区名を入れ、モデルが書いた名前を API が ID に直す |
| 失敗 | 失敗しない（DB の障害を除く） | 502（模擬には切り替えない） |
| 再現性 | 同じ入力なら同じ出力 | 同じ入力でも、答えが変わりうる |
| 費用・外部通信 | なし | 無料枠。Google へ質問の文面が出る |

## やり直し方

- `.env` の `LLM_PROVIDER` を空にするか消し、api を再作成する（`docker compose up -d api`。コードの変更は要らない）。模擬に戻る。キーは、不要なら Infisical（または `.env`）から消し、AI Studio で無効にする。
- 実 LLM のコードごと外すなら、`backend/app/chat/gemini_model.py`・`service.py` の `llm` 引数・`routes.py` の 502・`config.py` の Gemini 項目・`main.py` の `llm` を戻す。

## 選ばなかった案

- **失敗時に模擬へ自動で切り替える**: 実 LLM の答えと模擬の答えを取り違える。検証（キーが効いているか）も隠れる。
- **キーを URL のクエリに付ける**: Google の標準の書き方の 1 つだが、URL は例外・ログ・プロキシの記録に残りやすい。ヘッダーで送る。
- **SDK（`google-genai`）を入れる**: 実行時の依存が増える（`httpx` なども）。呼ぶ API は 1 つなので、標準ライブラリの `urllib` で足りる。
- **LLM に結果の数字も書かせ、あとで検査する**: 文が数字だらけになり、検査で替わる回数が増える。数は結果のカードに任せ、文には書かせない。（**2026-11-26 に、この案を採ると改めた。[ADR 0009](0009-llm-writes-result-numbers.md)**）

## 追記 2026-11-25: 実測を受けた、既定モデルの変更と再試行

上の本文のうち、**モデルの既定**・**待ちの上限（上限の行の「超えたら失敗」。再試行の記述は無く、実質は再試行なし）**・最後の「未確認」の Next.js の項は、この追記が新しい（本文は書き換えず、残す）。

**実測**（2026-11-25。実際の Gemini API を呼んだ測定）:

- `gemini-3.1-flash-lite`: 503（high demand）とタイムアウトで、質問 7 問すべてが失敗。最小の呼び出しも 3 回中 3 回失敗。
- `gemini-3.5-flash-lite`: 32 回中 28 回成功。失敗 4 回は、503 が 3 回・タイムアウトが 1 回。待ちは、平均 5.8 秒・通常およそ 2 秒・最大 21 秒。

**決めたこと**:

- **既定の `GEMINI_MODEL` を `gemini-3.5-flash-lite` に変える**（`app/config.py` の `DEFAULT_GEMINI_MODEL`）。DocuNavi の既定とは、ここで分かれる。`GEMINI_MODEL` で上書きできるのは、いままでどおり。
- **一時的な失敗だけ、再試行する**: HTTP 5xx・タイムアウト・接続エラーを、チャット 1 回の要求につき最大 1 回（往復ごとではない）、1 秒待ってやり直す。実測の失敗（503・タイムアウト）は、この種類。4xx（429 を含む）は、やり直さない（無料枠の上限は、待っても直らない。キー・モデル名の誤りも直らない）。壊れた応答（JSON が読めない・大きすぎる）も、やり直さない。やり直したことは、種別（`server`・`timeout`・`network`）と HTTP のステータスつきで、ログに残す（キー・URL・本文は出さない）。
- **要求全体に期限（27 秒）を置く**: 往復・ツールの実行・再試行・待ちの全部を含む。各呼び出しの待ちは、20 秒と残りの期限の小さいほうにする。待ったあとの残りが 5 秒に満たないときは、やり直さず、新しい往復も始めない（その失敗の種類は `deadline`）。再試行を含めても、各呼び出しが渡した待ちの内に終わるなら、最悪で 27 秒（20 秒のタイムアウト → 1 秒待つ → 残り 6 秒の呼び出し）。
- 期限を 27 秒にした理由: frontend の Next.js が `/api/*` を転送するときの待ちの既定は 30 秒（インストール済みの next 16.4.6 の `proxy-request.js` が `proxyTimeout || 30000`、`next.config.ts` は変えていない。**ソースを読んだだけで、実機では未測定**）。これより前に API が 502 を返せば、画面は既存の失敗表示（送信できませんでした＋もう一度送る）になる。期限が無いと、本文の「最悪 4 往復（80 秒）」は、転送が先に切れる。
- 失敗時の挙動は変えない: 再試行しても失敗したら、模擬に切り替えず HTTP 502（`llm_unavailable`）。応答・ログにキーを出さない。

**残る不確かさ**: 20 秒のタイムアウトは、接続・受信の各段階ごと（urllib の `timeout`）で、少しずつ届く応答の全体を切るものではない。期限は、呼び出しの前後でだけ数える（呼び出しの途中では切らない）。実測の最大 21 秒は、この 20 秒に近い。`gemini-3.5-flash-lite` の関数呼び出し・日本語の質・無料枠の制限は、本文の「未確認」のとおり。

## 追記 2026-11-25（開発・実行の既定を Gemini にする）

- ユーザー決定（「基本 LLM にしといた方良くない？」「ずっとモック鬱陶しかった　紛らわしいし」）。`compose.yaml` の `LLM_PROVIDER` の既定を `mock` から `gemini` にした。キー（`GEMINI_API_KEY`）は Infisical か `.env`（ユーザーが `scripts/login-secrets.sh` で登録する。私は値を読まない）。無料キーなので費用は出ない（本文のとおり）。
- 本文の「既定は `mock`」は、**Go の API 自体の既定（環境変数が無いとき）**として残る。契約の検査（`contract/`・`scripts/test-contract.sh` は `LLM_PROVIDER=mock` を明示）と Go・ローダーのテストは、答えが決まっている模擬が要るので、変えない。
- 模擬は**利用者は使わない**（ユーザー決定 2026-11-25）。使うのは、Claude Code が内部で検証するときだけ: `scripts/with-mock-llm.sh <コマンド>`（コマンドの間だけ api を模擬にし、終わったら自動で gemini へ戻して確かめる。戻し忘れを仕組みで防ぐ）。どちらで動いているかは `/api/health` の `llm`（`mock`／`gemini`）で見る。

- 根拠（今回の Web 検索。実務者のブログ中心で、公式の標準ではない）: テストはモック・再生、振る舞いの確認は実モデル、という層に分けるのが主流。
- 戻し忘れの防止（2026-11-25）: 入口は `scripts/with-mock-llm.sh`（自動で戻す）。フック `scripts/hooks/pretool-guard-llm.sh`（手での切り替えを拒否）と `stop-check-llm.sh`（模擬のまま終えようとしたら 1 回だけ止める。`stop_hook_active` なら通す・api に届かなければ通す・確認は最大 2 秒）。実測は 1 回 0.02〜0.06 秒。**ガードであり、完全な防御ではない**: Claude Code を通さない操作、別のスクリプト・設定ファイル経由、MCP は防げない。VS Code 拡張で Stop フックが動くかは未確認。
