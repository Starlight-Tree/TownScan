# 0009 チャットの返答文: 結果にある数字は LLM が書いてよい（検査で止める）

状態: **承認（2026-11-26。ユーザーが「下のカードのとおりなら、チャットの意味がない」と指摘し、私の提案に「y」）**。[ADR 0003](0003-llm-provider.md) の「数字は書かせない」と、見送った案「LLM に結果の数字も書かせ、あとで検査する」を改める。

## 背景

- ADR 0003 は、LLM に数字を書かせず、返答文を「結果は下のカードのとおりです」に寄せた。実画面で、本文が案内だけになり、説明がカードと図に分かれて、チャットの価値が薄かった（ユーザー指摘）。
- 返答文の数字の検査（`guard.go`）は、すでにある。結果の値だけから出ていない数字（漢数字・英語の数詞・区切った数を含む）を見つけると、固定文に替える。禁止は、指示（`gemini_model.go`）だけが担っていた。

## 決定

- **数字・件数・面積は、ツールの結果に書かれている値だけを、半角のアラビア数字でそのまま書いてよい。** 足し算・割合・概数・結果にない数字は書かせない（書くと検査が固定文に替える）。座標と ID は、これまでどおり書かせない。
- 返答は 2〜4 文: 1 文目で質問に答え、結果から読み取れる要点と、注意点（判定保留は目で確かめる候補、など）を添える。「下のカードのとおり」だけで終えない。
- **カードや図の位置の語**（上の・下の・右の・左の・上記・下記）は、書かせない。画面の並びは変わりうる（ADR 0007・0008）。指示で言い、`guard.go` でも止める（「上の/下のカード」は方向の語だけ取り除く。「上記」「下記」は固定文に替える。「以上の」「以下の」は残す）。
- **検査が止めるのは、数字と位置の語だけ。** 数字以外の主張（「最も多い」「過半」「確信度が分かれる」など）は、検査の外にある。指示で「結果の数字を見比べて確かめられるときだけ使う」と言うが、確率的にしか守られない。

## 見送った案

- **数字以外の主張も検査する**（評価の語の許可リスト・結果からの再計算）: 範囲が広く、今回の用途では見合わない。ログの回数を見て、必要なら別に決める。
- **精度の回答に「F1 0.16 は低い」と評価を書かせる**: 閾値の根拠がなく、結果にない主張になる。数字を並べる今の形のまま。評価を足すなら、仕様に閾値を決めて、画面側で作る文にする。
- **LLM の失敗（502）の再試行を増やすこと**（今の 1 回より多く）: 試行 15 回中 1 回の失敗だけで、頻度が分からない。頻度を見てから。

## 影響・根拠

- ADR 0003 が見送った理由は、「文が数字だらけになり、検査で替わる回数が増える」だった。実 Gemini で試した 15 回（件数・比較・一覧・地図・精度の 5 問を 3 回ずつ。1 回は LLM の失敗で、返答は 14 件）では、固定文への差し替えは 0 回だった。ただし、同じ質問の揺れしか見えておらず、頻度が低いとは言い切れない。
- 差し替えた回数と、そのときのツール名は、ログに残る（本文・数字は出さない）。位置の語を取り除いた回数も、同じく数える。普段の利用で数えて、増えるようなら、指示を直すか、この決定を見直す。
- この試しで、結果にない言い方が 3 件あった（「確信度が分かれており」・件数の回答の「カードの写真」・地図の回答の「地区ごとの位置」）。許容して様子を見る。
- 出どころ: 「ツールの結果と照合して検査する」が一般的な実務、という私の一般知識（今回の検索で裏づけたものではない）。
- 画面側: 比較のカードの要点（`compare-summary.ts`）が、本文と重なるようになる。残すか削るかは、画面を見て決める。
