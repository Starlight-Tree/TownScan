# 0013 回答は、短い本文と表示 1 つにする

状態: **承認（2026-11-26。ユーザーが実画面を見て順に指示・承認し、最後に「y」）**。次を改める: [ADR 0012](0012-photo-cards-in-answers.md) の「分類の情報は残す」と「根拠を見る」の位置、[ADR 0011](0011-class-labels-by-observation.md) のうち回答の中で分類を呼び名で出すこと、[ADR 0009](0009-llm-writes-result-numbers.md) の「返答文は LLM が書く」（件数だけの回答と、追記で写真 1 件だけの回答に限る）、[ADR 0008](0008-full-width-tabs.md) の回答の並びと「閉じる」の扱い。**分類の決まり・分類のキー・DB は変えない**。

## 背景

ユーザーが実画面を見て指摘した。

- 回答に表・グラフ・画像・地図が重なって重い。
- 本文の分類の内訳や、画面を見れば分かる説明が分かりにくい。実 Gemini が、意味の通らない写真の説明を書いた（私の指示の「中身を 2 文目で説明する」「写真は『各候補の詳細の写真』と書く」が原因）。
- 「根拠を見る」の中身（モデル・実行・ツール）、「対象・条件」の帯、「詳細」「チャットへ戻る」「閉じる」の文字は要らない。

## 決定

- **本文の下の表示は 1 つ。順位で決める**: 地図の表示 ＞ 候補 1 件の写真 ＞ 地区の比較 ＞ 候補の一覧 ＞ 件数。2 位以下と、同じ対象の地図・グラフは、最新の回答の下の「表示を切り替える」に 2 つまで出す（押しても質問は送らない）。順位はコードの決まりで、同じ結果にはいつも同じ表示になる。
- **件数だけの回答の本文は、コードが組み立てる**。多い地区の順位もコードが計算し、結果の `area_ranking` に入れる。ツールを選ぶのは LLM のまま。複数のツールを使った回答などの本文は LLM が書き、数字の検査もこれまでどおり。
- **写真 1 件だけの回答も、LLM の文を使わない**（追記 2026-11-26 夜。承認: ユーザーの「y」）。本文は、結果の説明（地区・面積・輪郭の注記）。実 Gemini が「左側に 2018 年、右側に 2023 年の写真を表示しています」と、指示に反して画面を説明した（公開中のスクリーンショットに写った）。模擬モデルの本文は変えない（模擬の振り分けは、前の本文に書かれた候補の ID で対象を引き継ぐ。実 LLM には ID を書かせないので、実 LLM に渡る会話にはもともと ID が無い）。
- **写真の対象は、言葉どおり最大の候補**（同じ追記）。分類の指定が無ければ、全分類で面積が最大のものを選ぶ。それまでは「2018 年は未検出」を先に選び、地区を指定すると最大でないことがあった（実データでは 2 地区）。薄場一丁目では、目視で橋の誤検出だった候補（142.25 m²）が出る。誤検出も、このアプリの限界としてそのまま見せる。全地区の最大（約 232 m²）は変わらない。
- **精度 1 件だけの回答も、LLM の文を使わない**（追記 2026-11-26 深夜。承認: 直す案にユーザーの「全て進めて」）。実 Gemini の本文は、回によって物体単位 F1 と「新築の再現率は未測定」を言わず、精度が実際より良く受け取られるおそれがあった。本文はコードが組み立て、この 2 つを必ず言う（ほかの数字はカード）。指示とツールは変えていないので、`evals/`（ツールの選択の評価）は流し直していない。模擬モデルの本文は変えない。
- **候補の一覧 1 件だけの回答も、LLM の文を使わない**（追記 2026-11-27。承認: ユーザーの「全てy」と、実 Gemini で調べる指示）。実 Gemini は、一覧の行を自分で数えて地区ごとの件数を 2 文目に書くことがあった。その件数は結果に無いので数字の検査に落ち、本文が固定文に替わった（シャトネ・マラブリーの一覧で、2 回目に再現。差し替え前の本文を一時的なログで確かめた）。本文はコードが組み立て、該当の全体の件数と、一部だけを載せたときはその件数を言う。主語は件数の本文と同じで、分類の名前は書かない。使い方の表の本文は変えない。指示とツールは変えていないので、`evals/` は一覧の 1 問だけを流し直した（2 回とも合格し、固定文に替わらなかった）。模擬モデルの本文は変えない。
- **お断り 1 件だけの回答も、LLM の文を使わない**（追記 2026-11-27。承認: ユーザーの「直して」）。「2020 年に建った建物は何件ですか？」で、本文が数字の検査の固定文（「結果は下のカードのとおりです。数字はカードに表示された値を見てください。」）になり、断る理由が分からなかった。API のログで、断りの回答が差し替わったことは確かめた（本文は残らないので、どの数字かは確かめていない。質問の年を書いたと推定）。本文は、結果の理由の文にする。この理由の文は、前から、写真の年以外の数字があれば固定の文に替えている。本文になるので、カードの位置の語があるときも固定の文に替える。指示とツールは変えていないので、`evals/` は断りの 5 問だけを実 Gemini で流し直した（5／5 が合格し、2020 年の質問の本文に理由が出た）。模擬モデルの本文は、もともとこの形。
- **回答の中では分類を出さない**。見出し・札・内訳・凡例・色分けを外し、回答の中の地図とグラフは 1 色にする。拡大ビューの地図・グラフ、候補の詳細、精度の画面は、分類を残す。
- **分類を指定した件数の本文は、条件を言葉で言う**: 「モデルが 2023 年の写真だけで見つけた候補」「モデルが 2018 年の写真でも見つけた候補」「判定できていない候補」（後の 2 つは、同じ形にそろえた起草者の追加）。「2018 年の写真に写っていない」とは書かない。確かめたのは「モデルが検出しなかった」ことまでで、目視で 2018 年側の取りこぼしがあった（ADR 0011）。
- **数えた範囲を言う**: 地区の名前は丁目だが、数えたのは約 130 m 四方の 1 区画。件数の本文に書く。
- **「根拠を見る」と「対象・条件」の行は、回答から外す**。写真の下には「出典：国土地理院」を残す（地理院タイルは、出典の記載が利用の条件）。モデル・実行などは、候補の詳細と精度の画面で読める。
- **写真を押して詳細を開く**。「詳細」「詳細を開く」の文字は置かない。
- **拡大ビューを閉じる手段は、右上の ✕ と Esc の 1 通り**。どの画面でも回答へ戻る。「チャットへ戻る」と、詳細だけを閉じる「閉じる」は無くす。
- 「続けて聞く」は 2 件まで（見出しの文字は出さない）。

## 見送った案

- **表示を選ぶのに、学習したモデルを使う**: 順位は結果の型だけで決まり、種類が少ない。コードの決まりで足りる。データの件数が増えても、型の選び方は変わらない。
- **件数の本文も LLM に書かせ、指示で形をそろえる**: 指示を変えるたびに実 API で確かめる必要があり、守られる保証が無い。
- **分類の決まり（縁の決まり）を先に直す**: 目視で、建物に見えない 3 件（川と鉄橋・地面・車）が「2018 年は未検出」に入るため、変えない（ADR 0011）。
- **固定の「確定ではありません」の 1 行を足す**: 説明を減らす方針に合わせ、「候補」という呼び方にとどめた。

## 調べたこと

2026-11-26 に検索した。**読んだのは検索の要約だけで、ページの本文は読んでいない。** 2026 年に限った根拠は見つからなかった。「回答の表示は 1 つ」を定めた根拠も見つからず、順位はこのアプリの判断。

- 画面に出す部品を、決まった一覧から選ぶ方式（[LangChain の解説](https://docs.langchain.com/oss/javascript/langchain/frontend/controlled-generative-ui.md)）と、詳しい内容をあとから見せる考え方（[解説](https://aiuxplayground.com/glossary/progressive-disclosure)）。
- 数字の取得と計算はコードで行い、LLM には文章化を任せる（[DEV Community の記事](https://dev.to/yaseen_tech/the-67-billion-numerical-hallucination-problem-454d)）。
- ✕ だけのボタンは意味が曖昧になりうるので文字のボタンを勧める記事（[NN/g](https://www.nngroup.com/articles/cancel-vs-close/)）と、効果の違う出口が複数あると迷う例（[NN/g](https://www.nngroup.com/articles/accidental-overlay-dismissal/)）。この画面は入力や保存が無く、出口を 1 つにしたので ✕ にした。

## 影響・残る点

- 写真 1 件だけの回答は、聞き方が違っても同じ形になる。「何階建て？」のような質問で写真のツールが選ばれると、本文はその問いに触れない。
- 写真 1 件のカードの題には、候補の ID が出る。
- **2 位以下の結果は、最新の回答からしか出せない。** 前の回答では、切り替えが消える。
- 件数と一覧の本文は、聞き方が違っても同じ形になる。
- 分類を指定した**一覧の題**と、別の解析結果の回答の比較の文には、分類名が残る。
- 比較・一覧・地図の表示の回答には、1 区画の大きさの注記が出ない。
- 使わなくなったコード（`AnswerScope.tsx` とそのテスト・CSS、チャットの `ToolCallContext`、結果カードの `notes` の部分、図の `withMap`）は消した。地図の表示のカードを出さないときの合成データの印は残した（`MapFocusCard` の `chipOnly`）。テストだけが使っていた 2 つの関数（`figureKinds`・`areaScopeHint`）も消した。
- **実 Gemini の確認（2026-11-26 夜。`evals/` の 18 問）**: はじめは 15 問が合格。屋根の太陽光パネル・取り壊し・衛星の 3 問は、断ってはいるが理由が `not_implemented` でなく `out_of_scope` だった。指示に理由の使い分けを足して流し直し、18 問が合格した（判定の基準は変えていない。各 1 回の実行で、毎回合格するとは限らない）。本文は判定の外で、地図・一覧の回答に「表示しました」と画面を説明する文が残る。精度の質問では、物体単位 F1 と「新築の再現率は未測定」を言わない回があった（上の追記で、本文をコードに替えた）。
- **未確認**: 指で押す画面の ✕、VoiceOver。狭い表示は、幅 500px で写真の回答・件数の写真のカード（1 列）・✕ だけを確かめた。
