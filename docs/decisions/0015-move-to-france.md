# 0015 対象をフランスに変え、新築の再現率を測る

状態: **下書き（2026-11-27）**。フランスで進める方向は、ユーザーの「フランスの方がいい」「それで進めて」で承認。アプリの置き換えは、ユーザーが画面を見て「OK」（2026-11-27）。**指標の定義と、F3 以降の出口条件は確認待ち。**確定したら、次を改める: [ADR 0002](0002-direction.md) の対象地域、[ADR 0014](0014-new-building-recall-unmeasured.md) の「新築の再現率は未測定」（フランスの評価では測る。熊本の値は未測定のまま）。

## 背景

- 熊本は、新築の正解になるデータが取れなかった（[ADR 0014](0014-new-building-recall-unmeasured.md)）。写真は 2018 年（帯状の範囲だけ）と 2023 年で、約 0.5 m/px。
- フランスには、前後 2 時点の空中写真と、新築を区別した建物の枠を組にした公開データ（FOTBCD）がある。屋根の太陽光パネルの学習データ（BDAPPV）にもフランスの画像がある。
- オランダも調べた。毎年の画像と建物台帳の建築年があり、ナイメーヘン北部の 1 か所で、2018 年の更地と 2023 年の住宅地を画像で確かめた。ユーザーは、新築とパネルの両方がそろうフランスを選んだ。

## 決定

- **対象をフランスにする。** 主役は、前後 2 時点の差分で見つける新築の候補。パネルは後の拡張のまま。
- **最優先は、今のアプリの画面と操作を、フランスのデータで使えること**（2026-11-27 のユーザーの指示）。日本の座標系・地理院のタイル・基盤地図情報・「2018／2023 年」の固定など、熊本向けの作りは残さず、フランスのデータに合わせて置き換える（合わない作りは作り替えてよい。同日の指示）。熊本のコードは git の履歴に残る。ローカルの DB の熊本の解析結果は消さず、フランスの結果を足す（API は作成日時が最新の結果を出す）。
- **地区は、県 92（パリの南西の近郊）の z18 タイル 12 枚。** 前は 2014 年、後は 2024 年。選び方（モデルを動かす前に固定）: val の 20 m² 以上の `NEW` の中心が多い順（同数は x・y の順）。12 枚の中の `NEW` は 37 棟。**新築の多い場所を選んでいる**ので、地区の件数は、県の全体の様子ではない。
- **画像は IGN の公開タイル配信**（data.geopf.fr の WMTS）の `ORTHOIMAGERY.ORTHOPHOTOS2014`（z18 まで）と `ORTHOIMAGERY.ORTHOPHOTOS2024`。
- **分類は「2014 年は未検出」と「未判定」の 2 つにする。** 熊本は、古い建物データに載っていない建物だけを候補にした。フランスでは差し引く建物データを使わず、後の写真の建物を全部、前の写真と比べる。前の写真でも検出した建物は、もとからある建物が大半になるので、候補から外す。
- **評価は FOTBCD の held-out（県 13・29・92）で行い、アプリの置き換えのあとにする。** それまで、精度の画面は「未測定」と出す。val は開発と調整に使う（上の地区選びにも使った）。test は、方式と閾値を決めたあとに 1 回だけ使う。それまで取得もしない。train（約 170 GiB）は使わない（学習するなら、別に決める）。

## 評価の定義（モデルを動かす前に固定する）

- **対象:** 評価する分割の全部の組（建物なしの組も含め、誤検出を数える）。
- **差分は写真だけで行う。** 熊本では、建物データ（基盤地図情報）に載っていないものを候補の入口にした。フランスで建物データ（BD TOPO）を入口に使うと、正解を見ることになるので使わない。後の写真の建物の抽出を入口にし、前の写真の抽出と比べて 3 分類する。
- **新築の再現率:** `NEW` の枠のうち、「前の写真では未検出」の候補と IoU ≥ 0.5 で 1 対 1 に対応した割合。
- **新築の精度:** 「前の写真では未検出」の候補のうち、`NEW` の枠と対応した割合。
- 併記: 「未判定」の候補も含めた再現率、県ごとの値と件数、建物の抽出の物体単位 F1（前の写真は `UNCHANGED`＋`DEMOLISHED`、後の写真は `UNCHANGED`＋`NEW` が正解）。
- **除外は、正解と候補で対称にする。** 画像の縁は [仕様 §6](../spec-prototype.md) の決まり。20 m² 未満は、候補を捨てるのに合わせて正解からも外し、自分の面積の半分以上がそれに重なる相手も外す。外した数を出す。
- **調整は val だけ。** 抽出の倍率は 0.5・0.625・1.0（512 px の画像を 256・320・512 px にする。0.4・0.32・0.2 m/px。モデルの入力は 32 の倍数が要る）、閾値は 0.3〜0.7（0.1 刻み）から、後の写真の建物の物体単位 F1 で選ぶ。分類の閾値は、最初は今の値（0.5・0.10・0.20）のまま測る。

## 限界

- val と test は、配布ページによると**人が選んで確認した組**で、無作為の標本ではない。数字は、県や地区の全体の実力ではない。
- 県は 3 つだけ。val と test は同じ県なので、test も別の地域の実力は示さない。
- 学習用の枠は自動で作られ、誤りを含みうる（評価には使わない）。
- 同じ場所は 2 時点だけで、撮影年は県で違う。毎年の変化は追えない。分類の呼び名の「2018 年」は、「前の写真」に改める必要がある。
- パネルは、増え方の正解が無い。[BDAPPV](https://zenodo.org/records/7358126) は 1 時点で、Google 由来の画像は Google の規約があるので、使うなら IGN の分だけにする。

## 置き換えて分かったこと（2026-11-27）

- 12 地区の 2014・2024 年の写真（24 枚）は取得できた。地区名は IGN の逆ジオコーダで取れた。配信の索引（WFS）では、12 地区とも 2014・2018・2021・2024 年の 4 回の撮影がある（2018・2021 年の画像は取っていない）。撮影日は 2014-05-17・06-06 と 2024-08-22。
- 今の抽出モデル（WHU で学習）は、Colab の T4 で 1 回流した。**目で見ると出来は悪い**（大きな新しい建物の見落としと、影を建物とする誤り）。数字では測っていない。
- 倍率 1.0・閾値 0.4 は、写真に重ねた図を目で見て選んだ固定の値で、検証していない。結果は 12 地区・候補 69 件（「2014 年は未検出」29・「未判定」40）。この件数は、実際の新築の数の目安にならない。
