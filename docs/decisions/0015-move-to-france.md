# 0015 対象をフランスに変え、新築の再現率を測る

状態: **承認（2026-11-27）**。フランスで進める方向は、ユーザーの「フランスの方がいい」「それで進めて」で承認。アプリの置き換えは、ユーザーが画面を見て「OK」。指標の定義と F3・F4 の出口条件は、案（精度の画面の val の値には「調整に使ったデータの値」と書く）への「y」で確定。次を改めた: [ADR 0002](0002-direction.md) の対象地域、[ADR 0014](0014-new-building-recall-unmeasured.md) の「新築の再現率は未測定」（フランスの評価では測る。熊本の値は未測定のまま。**アプリへ載せる（F3 ③）まで、画面の表示は「未測定」のまま**）。

## 背景

- 熊本は、新築の正解になるデータが取れなかった（[ADR 0014](0014-new-building-recall-unmeasured.md)）。写真は 2018 年（帯状の範囲だけ）と 2023 年で、約 0.5 m/px。
- フランスには、前後 2 時点の空中写真と、新築を区別した建物の枠を組にした公開データ（FOTBCD）がある。屋根の太陽光パネルの学習データ（BDAPPV）にもフランスの画像がある。
- オランダも調べた。毎年の画像と建物台帳の建築年があり、ナイメーヘン北部の 1 か所で、2018 年の更地と 2023 年の住宅地を画像で確かめた。ユーザーは、新築とパネルの両方がそろうフランスを選んだ。

## 決定

- **対象をフランスにする。** 主役は、前後 2 時点の差分で見つける新築の候補。パネルは後の拡張のまま。
- **最優先は、今のアプリの画面と操作を、フランスのデータで使えること**（2026-11-27 のユーザーの指示）。日本の座標系・地理院のタイル・基盤地図情報・「2018／2023 年」の固定など、熊本向けの作りは残さず、フランスのデータに合わせて置き換える（合わない作りは作り替えてよい。同日の指示）。熊本のコードは git の履歴に残る。ローカルの DB の熊本の解析結果は消さず、フランスの結果を足す（API は作成日時が最新の結果を出す）。
- **地区は、県 92（パリの南西の近郊）の z18 タイル 12 枚。** 前は 2014 年、後は 2024 年。選び方（モデルを動かす前に固定）: val の 20 m² 以上の `NEW` の中心が多い順（同数は x・y の順）。12 枚の中の `NEW` は 37 棟。**新築の多い場所を選んでいる**ので、地区の件数は、県の全体の様子ではない。
- **画像は IGN の公開タイル配信**（data.geopf.fr の WMTS）の `ORTHOIMAGERY.ORTHOPHOTOS2014`（z18 まで）と `ORTHOIMAGERY.ORTHOPHOTOS2024`。
- **分類は「2014 年は未検出」と「未判定」の 2 つにする。** 熊本は、古い建物データに載っていない建物だけを候補にした。フランスでは差し引く建物データを使わず、後の写真の建物を全部、前の写真と比べる。前の写真でも検出した建物は、もとからある建物が大半になるので、候補から外す。
- **評価は FOTBCD の held-out（県 13・29・92）で行い、アプリの置き換えのあとにする。** それまで、精度の画面は「未測定」と出す。val は開発と調整に使う（上の地区選びにも使った）。test は、方式と閾値を決めたあとに 1 回だけ使う。それまで取得もしない。train（約 170 GiB）は使わない（学習するなら、別に決める）。

## 評価の定義（モデルを動かす前に固定する）

- **対象:** 評価する分割の全部の組（建物なしの組も含め、誤検出を数える）。
- **差分は写真だけで行う。** 熊本では、建物データ（基盤地図情報）に載っていないものを候補の入口にした。フランスで建物データ（BD TOPO）を入口に使うと、正解を見ることになるので使わない。後の写真の建物の抽出を入口にし、前の写真の抽出と比べて 3 分類する。
- **新築の再現率:** `NEW` の枠のうち、「前の写真では未検出」の候補と IoU ≥ 0.5 で 1 対 1 に対応した割合。
- **新築の精度:** 「前の写真では未検出」の候補のうち、`NEW` の枠と対応した割合。
- 併記: 「未判定」の候補も含めた再現率、県ごとの値と件数、建物の抽出の物体単位 F1（前の写真は `UNCHANGED`＋`DEMOLISHED`、後の写真は `UNCHANGED`＋`NEW` が正解）。
- **除外は、正解と候補で対称にする。** 画像の縁は [仕様 §6](../spec-prototype.md) の決まり。20 m² 未満は、候補を捨てるのに合わせて正解からも外し、自分の面積の半分以上がそれに重なる相手も外す。外した数を出す。**この除外は、建物の抽出の F1（前後の両方。設定の選択を含む）と、新築の指標のすべてにかける。**
- **調整は val だけ。** 抽出の倍率は 0.5・0.625・1.0（512 px の画像を 256・320・512 px にする。0.4・0.32・0.2 m/px。モデルの入力は 32 の倍数が要る）、閾値は 0.3〜0.7（0.1 刻み）から、後の写真の建物の物体単位 F1 で選ぶ。同点は、倍率が小さい → 閾値が 0.5 に近い → 閾値が小さい、の順。新築の指標は、選んだ値でだけ計算する。分類の閾値は、最初は今の値（0.5・0.10・0.20）のまま測る。
- **建物の取り出しは、アプリと同じ手順。** 4 m² 未満の粒と穴を消し、輪郭を単純化する（地上の 0.2 m。アプリの 0.3 m は Web メルカトルの長さで、県 92 ではほぼ同じ）。前の写真との重なりは、前の写真の建物の全部（除外の前）で計る。
- **val の値を見せるときは、「調整に使ったデータの値」と書く。**
- **併記（案への「y」。2026-11-27。val でモデルを動かす前に追加）:** 端の除外だけを外した値も、全体と県ごとに出す（建物の抽出の F1 と新築の指標）。20 m² 未満の建物と、それと半分以上重なる相手を外す決まりは同じ。端で切れた正解と予測の形どうしを、同じ IoU で比べる。端の建物も、ほかの建物と同じ写真の比較で分類する（アプリの「端のため未判定」は使わない。使うと、端の建物は「未検出」に 1 件も入らない）。**主な値と、倍率・閾値の選択は、上の定義のまま。**

上の「全部の指標に除外をかける」・同点の順・取り出しの手順は、実装のときに書き足した（2026-11-27。val でモデルを動かす前）。入出力の形は[仕様 §6.1](../spec-prototype.md)。

## 指標を実装して分かったこと（2026-11-27。モデルは使っていない）

- 実装で読んだ val の件数・県ごとの値・`NEW` の面積は、上の「取得した val の中身」と一致した。
- 下の数字は、実装の関数を一時のスクリプトから呼んで出した（スクリプトは repo に入れていない）。
- **端の除外が大きい。** 後の写真の正解 3,981 のうち、2,295 が組の端に接する。倍率 1.0 で指標の対象になる `NEW` は、1,231 のうち **474**（県 13 は 215・29 は 249・**92 は 10**。下の確認の数え方で、予測にも正解の枠を使った場合）。アプリの地区がある県 92 の値は、10 件では傾向も言えない。
- **正解の枠をそのまま予測にしても、新築の再現率は満点にならない。** 正解の枠を塗った配列（0 か 1）を前後の予測にして測った（閾値 0.5）。倍率 1.0 で、建物の抽出の F1 は前 0.974・後 0.966、**新築の再現率 0.844**（未判定を含めると 0.901）・精度 0.990。倍率 0.5 の再現率は 0.837。
- 拾えない 74 件の内訳: **45** は、予測の塊と IoU 0.5 に届かず、ほかの建物の枠と接する（0.25 m 未満。隣とつながって 1 つの塊になる）。**25** は、取り壊しの跡（`DEMOLISHED` の枠と 10% 以上重なる）で、前の写真にも建物がある（未判定 23・候補にしない 2）。**4** は、そのほかの未判定。
- このため、モデルの結果の再現率は、**この方式の上限の目安（約 0.84）と並べて読む**。隣の建物をすき間で分けて出すモデルなら超えうるので、厳密な上限ではない。
- **併記でも同じ確認をした**（閾値 0.5。本体の値は、上と一致した）。倍率 1.0 で、対象の `NEW` は **1,094**（1,231 から 20 m² 未満の 137 を除いた数。県 13 は 520・29 は 506・**92 は 68**）。建物の抽出の F1 は前 0.977・後 0.966、**新築の再現率 0.810**（未判定を含めると 0.883）・精度 0.991。倍率 0.5 の再現率は 0.807。**県 92 の再現率は 0.43**（本体の値では 10 件で 0.60）で、理由は調べていない。併記の上限の目安は約 0.81。

## val の結果（2026-11-27。調整に使ったデータの値）

- **設定の調整では、大きく変わらない。** 15 通りの後の写真の F1 は 0.266〜0.315。閾値は探索の範囲の下端が選ばれたが、倍率 0.625 の F1 は、閾値 0.3 で 0.3153・0.4 で 0.3149 と、ほぼ同じ。範囲は、結果を見たあとなので変えない。

## 限界

- val と test は、配布ページによると**人が選んで確認した組**で、無作為の標本ではない。数字は、県や地区の全体の実力ではない。
- 県は 3 つだけ。val と test は同じ県なので、test も別の地域の実力は示さない。
- 学習用の枠は自動で作られ、誤りを含みうる（評価には使わない）。
- 同じ場所は 2 時点だけで、撮影年は県で違う。毎年の変化は追えない。分類の呼び名の「2018 年」は、「前の写真」に改める必要がある。
- パネルは、増え方の正解が無い。[BDAPPV](https://zenodo.org/records/7358126) は 1 時点で、Google 由来の画像は Google の規約があるので、使うなら IGN の分だけにする。
